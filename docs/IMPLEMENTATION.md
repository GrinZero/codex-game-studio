# 第一轮实现与下一阶段

日期：2026-10-09。基线：用户提供的 Codex_Game_Studio_Product_Design_v0.1.docx。该文档作为产品需求参考；其中的建议、来源与操作描述不被当作额外执行授权。

## 第一轮交付

空仓库现已形成可运行的 React 工作台、TypeScript Core、SQLite 存储、HTTP 与 stdio MCP。第一轮采用原创 UI 和领域实现；尚未抽取 ohmygame 模块。视觉方案采用海军蓝工作区、浅蓝操作与灰绿完成状态，素材卡与画布内制作卡是核心对象。

模型与媒体预览：HTTP 工作台直接使用二进制文件路由。MCP 内嵌版通过工具取得绑定单个文件、5 分钟有效的签名 HTTP 链接，再以 `fetch → Blob → object URL` 读取；CSP 仅新增本机服务的连接来源，其他 API 保持同源限制。宿主无法访问本机 HTTP 时回退到 512 KiB MCP 分块。内嵌预览按使用者计数共享传输与 Blob URL，最后一个使用者离开后取消读取、回收 URL 并移除缓存；下载期间也持有引用。签名密钥只保存在登记库目录的 `asset-http.key`（0600），不传给界面。

这轮重点实现 M1 基础底座及 M2 的人工制作路线。不是将原设计全部标为完成。

## 必须保留的约束

1. projectId 与不可变 revisionId 明确传递；资源列表的最新版本不替代画布或流程采用版。
2. layoutRevision 和 graphRevision 分开，CAS 在 SQLite 事务中执行；Agent 导入与 UI 移动共享状态。
3. 产物先落临时目录并校验，然后移入版本目录，再发布数据库记录。事务失败后未登记目录保留；恢复核对/清理工具尚未完成。
4. 运行固定模板、graphRevision、输入版本；旧运行与输出保留。当前局部重跑是线性链路，不宣称独立头身分支。
5. 浏览候选不创建审核；审核在当前 Run revision 下绑定输入与明确输出。授权的 Agent 决定记录 delegated_agent，后端身份认证/独立策略审计仍需后续扩展。
6. 导出的技术 passed 仅为已实现的文件结构与完整性范围，用户观察、Blend 实际打开与引擎验收需独立证据。
7. 无 Provider 时不创建模拟付费 Job，也不以零费用代替未知估算。当前 manual 路线记录 estimate=null / not_applicable。

## 下一轮顺序

- M0：在目标 Codex 原生宿主观察入口和生命周期；验证上下文消息与文件入口。MCP 资源、沙箱桥接、本地开发包和缓存外运行时已实现。
- 完整画布编辑：分组、图语义撤销/重做、节点绑定更新、CAS 冲突保留本地待提交操作。
- Provider：选定实际 API 或网页辅助方式；实现 capability、submit、poll/reconcile、cancel、materialize 和 cost。
- 持久 Job：operationId、幂等键、providerTaskId、submitting/reconciling；对不明确的提交禁止自动重发。
- 角色分支：头、身体独立产出/审核、组装与依赖传播；只重跑身体及组装下游。
- Worker：检查 GLB 预算、实际打开 Blend、Godot 导入，追加 ValidationRecord 证据；不会用预览代替验收。
- M4：ohmygame 只读预览迁移、一致性备份、项目目录恢复 UI、第三方许可库存与安装试用。

下一轮需要的配置事实包括首个模型服务、额度来源与目标 Codex 宿主能力。现有的本地基础体验不依赖这些配置。
