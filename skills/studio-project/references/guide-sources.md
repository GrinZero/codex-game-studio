# 来源对照与设计取舍

[返回规范](project-file-guide.md) · 版本 1.2 · 参考日期：2026-10-13

本规范根据两份指南进行有选择的改编，并补充独立开发者使用插件时需要的采用流程、源文件边界和交付规则。以下表格用于核对来源覆盖情况，不把本项目新增建议归功于原文，也不将社区约定表述为引擎强制标准。

## 1. 参考版本与许可

- **Allar / Gamemakin：** [ue5-style-guide 的 main README](https://github.com/Allar/ue5-style-guide/blob/main/README.md)。仓库名包含 UE5，但本文所读 main 的顶部说明仍以 UE4 为基础，UE5/v2 见其 v2 分支；本规范不宣称完整覆盖 v2。上游采用 MIT，保留[许可全文](third-party/allar-MIT.txt)。
- **bakneko：** [godot-style-guide 的 main 中文 README](https://github.com/bakneko/godot-style-guide/blob/main/README.zh.md)。该文自身引用 Allar 指南，两者有共同来源，不能视为两份独立行业标准。上游采用 MIT，保留[许可全文](third-party/bakneko-MIT.txt)。

原作者的命名和组织思想保留明确来源。本文示例、规则编号、统一词典、适用条件及插件采用机制为 Open Game Studio 的编排和补充。参考为以上分支在参考日读取的内容，不声称是固定提交或未来最新版。

## 4. 冲突与通用化决策

| 两份原文的具体差异／局限                                       | 本规范的决定                                     | 原因                                             |
| -------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------ |
| Allar 倾向 PascalCase 和类型前缀；Godot 使用 snake_case 与后缀 | 通用后缀规则＋引擎适配                           | 保留辨识度和工具习惯，避免同一文件同时套两套规则 |
| Allar 反对冗余类型目录；Godot 示例仍有 meshes 层               | 内容／功能优先，允许有用途的类型分组             | 查完整资产方便，资源多时仍能拆分                 |
| Allar 讨论实验可进入源控；Godot 建议忽略 sandbox               | 明确本地或协作实验，再决定源控；发行排除独立设置 | 避免丢失协作内容，也避免实验流入发行包           |
| Allar 原表中部分缩写跨类型复用，如 A\_ 和 \_M                  | 通用词典用完整语义；UE 项目维护选定词典          | 文件夹外也尽量可读，减轻新人记忆负担             |
| Godot 不同示例的用途／变体顺序并非完全一致                     | 新文件固定变体在用途之前，旧文件保留或显式迁移   | 给用户可直接执行的一套规则                       |
| 模型、纹理条目含特定引擎或旧管线假设                           | 技术规则注明适用条件和证据                       | 兼容程序化材质、动态光照、不同 LOD 与平台方案    |
| UE 蓝图细节、历史技术类型、商店提交要求                        | 保留相关组织原则；不逐条转写成跨引擎规则         | 文件规范不承担完整编程风格或商店准入文档的职责   |

## 5. 本项目补充的部分

源文件／导出物／参考／缓存分工、身份／变体／修订分离、不可变交付、生成来源、工作台受管数据保护、渐进迁移、规则严重度、可选采用和项目约定模板，属于面向插件用户的补充设计。

模型与贴图检查借鉴原文后作适用性调整；骨架、2D/UI、音频和跨引擎导出检查进一步补充。具体技术参数必须结合实际工具验证；本规范没有宣称这些规则已经作为插件自动检查功能实现。

## 6. 版本控制适配的补充依据

版本 1.2 将修订、忽略、同步、文件锁与保存方式从 Git 特定表述抽象为通用要求；原指南对版本控制的用法仍按原文归属，未据此假定所有用户都使用 Git。新增 [VCS 适配](version-control.md)依据 Diversion 的仓库／分支／工作区、同步、软硬锁、忽略与选择性下载文档，并参考 Git/LFS、Perforce 和 Unity Version Control 的官方文档。具体来源链接与适用条件位于该适配文件各节。

这些工具事实为公开文档的摘要与项目约定设计，实际能力须结合客户端版本、账户和仓库配置核实。本规范不替代各工具操作文档，也不宣称插件已实现服务端连接器。
